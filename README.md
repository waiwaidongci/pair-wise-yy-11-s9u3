# hxyfront-62010 潜水气瓶充填工位闭环

给潜水店使用的气瓶充填工位前端系统。从配气单排队、开工锁定、气源失效暂停/换批续充、
实测公差判定、留档复核到签收、签收后换单回队列，形成单瓶全流程闭环。

## 闭环规则

- **编号唯一**：气瓶编号全局唯一，重复登记直接拒绝。
- **开工三拦截**：检验过期/送检中、目标压力超过公称耐压、余气与目标气体冲突（余氦、余氧过高等）
  时不得开工，队列卡片只提供 **排空** 或 **送检** 两个出口。
- **一工位一瓶**：开工同时锁定气瓶、操作员、气源批次、工位；录入实测后工位才释放。
- **气源失效**：批次标记失效后，使用该批次的进行中充填自动暂停；必须换用合格批次，
  重验检验有效期、气源兼容性通过后才能续充。
- **实测公差**：压力不高于目标且不低于目标 −3%，O₂ ±1.5%，He ±2.0%。
  超限不阻断流程，但只留档转复核；复核仅追加结论与意见，**实测值冻结不可修改**，
  通过则放行签收，驳回则配气单回队列重充（实测记录仍留档）。
- **签收后换单**：原签收配气单置为失效（VOID），新配气单回到待充填队列。
- **并发开工仅一次**：所有写操作经互斥队列串行提交；同一配气单/工位的重复并发开工，
  第二次在状态复核时必被拒绝。页面工具栏提供"并发开工自检"按钮演示。
- **刷新一致**：状态持久化在 localStorage，并监听 storage 事件同步多标签页；
  队列、工位、历史刷新后保持一致。

## 架构（规则 / 存储 / 展示分离）

```
src/
  domain/
    types.ts        # 实体与状态类型
    rules.ts        # 纯函数规则：检验/耐压/余气/气源兼容/工位/公差判定（不依赖 React/存储）
  store/
    store.ts        # 唯一状态、action 互斥队列、localStorage 持久化、跨标签页同步
    selectors.ts    # 队列、工位、历史、待签收/复核等派生视图
  components/       # 展示层：队列、工位、复核签收、批次、登记换单、单瓶历史
```

## 技术栈

React 19 + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62010

种子数据含：4 个气瓶（含 1 个已过期 TANK-188、1 个临期 TANK-231）、4 个气源批次
（含 1 个已失效高氧批次）、2 个工位和 4 张待充填配气单。可用"重置演示数据"恢复。
